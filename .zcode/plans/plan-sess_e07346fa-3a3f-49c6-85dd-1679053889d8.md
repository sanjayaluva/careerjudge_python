# Implementation Plan — Reports 2 & 3 (Psychometric + Training + Counselling)

## Resolved decisions (from Q&A)
1. **Forced-choice scoring** → Follow the *Report*: replace single `predefined_score` with `selection_score` + `non_selection_score` (default 1/0; rule: selection > non-selection ≥ 0). Both options in a pair post a score to their own section.
2. **Psychometric "section"** → Reuse `assessment.AssessmentSection`. Options carry a portable `section_tag` label (set at question creation); at assign-time the `section_tag` is matched to an `AssessmentSection` in the target assessment so scores roll up correctly.
3. **Help Desk** → Add a new `helpdesk` role (additive; accounts module allows custom roles at `models.py:103`).
4. **Trainer QB/assessment access** → Scope both Question Bank questions and Assessments to `created_by=trainer` (trainer sees only their own).

## Phase A — Psychometric Question Types (Report 2)

### A1. Schema — option→section tagging + forced-choice scores
Migration `question_bank/0013_psychometric_option_sections.py`. Add to `ResponseOption` (`question_bank/models.py:482`):
- `section_tag` — `CharField(max_length=100, blank=True)` — portable label (e.g. "Leadership"). Drives per-section scoring.
- `selection_score` — `FloatField(default=1.0)` — forced-choice: score when this option is **selected**.
- `non_selection_score` — `FloatField(default=0.0)` — forced-choice: score when **not selected**.
- Keep `predefined_score` for backward-compat (deprecated; mapped to `selection_score`).

### A2. Question-text-2 on psychometric editors (Common Issue 1)
- `PsychometricEditors.tsx`: add a second `WysiwygEditorLite` bound to `question_text_2` in all 4 editors (Rank, RankRate, Rating, ForcedChoice).
- `QuestionEditorPage.tsx:787-803`: include `question_text_2` in `rankData/rankRateData/ratingData/forcedChoiceData` + load it in `populateForm`.
- Player already renders HTML Text 2 (verified) — no player change beyond the forced-choice answer shape.

### A3. Section-tag UI in editors (Common Issue 3)
- Rank / RankRate editors: per-option `section_tag` input. Validation: N options ↔ N **distinct** non-empty tags (enforced in `validation.py:157-185`).
- ForcedChoice editors: each of the 2 options gets a `section_tag`; validation rejects pairs where both tags are equal ("two options from same section cannot be paired").
- ForcedChoice replaces per-option `predefined_score` input with `selection_score` + `non_selection_score` inputs (rule enforced in validation: selection > non-selection ≥ 0).

### A4. Scoring engine rewrite (`assessment/scoring.py`)
- `_score_rank` (`:345`): rewrite → per-option `score = N − rank + 1`, keyed by option; max = N (not pair-count).
- `_score_rank_rate` (`:386`): formula already correct; keep, but emit per-option results.
- `_score_forced_choice` (`:448`): selected option → `selection_score`; non-selected → `non_selection_score`. Both posted.
- `_score_forced_choice_rated` (`:476`): selected → `selection_score × rating`; non-selected → `non_selection_score`.
- `_get_max_score` (`:79-98`): RANK → N; RANK_RATE → N × max_rating; FORCED_CHOICE → max(selection_score, non_selection_score); FORCED_CHOICE_RATED → max(selection_score × max_rating, non_selection_score).
- **New per-section aggregation path** in `calculate_session_scores` (`:706`): for psychometric attempts, after scoring, split the question's score across sections using each option's resolved `AssessmentSection` (via `section_tag` → section map built per assessment). Non-psychometric types keep the existing single-section path.

### A5. section_tag → AssessmentSection resolution at assign
- In `AssessmentQuestionViewSet.create` (the auto-expand path), when attaching a psychometric question, resolve each option's `section_tag` to an `AssessmentSection` of the assessment (by title match); unresolved tags → create a leaf section under the question's assigned parent. This keeps the authoring model portable while giving the scoring engine real section FKs.
- Expose `section_tag`, `selection_score`, `non_selection_score` in `ResponseOptionSerializer` + the frontend types (`questionBank.ts`).

### A6. Player + results display
- `SessionPlayerPage.tsx` forced-choice branch: keep the 2-option pair UI; capture `selected_option_id` (+ `rating` for two-level). Results/debug view shows **two** section contributions per pair.

### A7. Tests (psychometric)
- Rewrite `test_scoring.py` rank/rate/forced-choice cases to the new formulas (rank-1→N; selection/non-selection; both-sections).
- New: `test_psychometric_section_aggregation` — multi-question, multi-section roll-up matches spec example (Q1-opt1 + Q2-opt3 → Section1 = 8).
- New: validation tests (N options ↔ N distinct tags; same-section pair rejected; selection > non-selection).
- Target: +18 tests.
